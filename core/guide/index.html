01 · START HERE

Install and open Core

Core runs on your own computer. The normal package includes its runtime, so you do not need Git, Node.js, npm, or database commands.

Choose your operating system to see the right launch steps.
Get Certifyd Core Beta 13
02 · FIRST RUN

Create the first owner

  1. Open Core's local dashboard at http://127.0.0.1:4000 if it did not open for you.
  2. On Create owner (first-run setup), make your owner account.
  3. Save the recovery key when Core shows it. It is shown once.

The dashboard on port 4000 is private operator access. Public tunnels use a separate, allowlisted listener on port 4010.

03 · IDENTITY

Make your profile yours

  1. In Core, open Profile → Public Profile (Presentation).
  2. Enter your display name and a short bio, then press Save.
  3. Review how the public profile looks before sharing its link.

Your local account and its public profile are related, but opening the private dashboard does not put your profile on the internet.

04 · PROFILE IMAGE

Add a profile picture

  1. Stay in Profile → Public Profile (Presentation) and find Profile image.
  2. Choose Upload image and select a picture up to 2 MB. Core also accepts an image URL in that field.
  3. Check the small preview. Core reports when the upload succeeds.

The picture is for your public presentation. It does not change who owns your local node.

05 · VERIFICATION

Create your first proof

  1. In Profile, create your Creator Identity if Core prompts you. Proofs are unavailable until this identity exists.
  2. Under Verification Proofs → Creator Platforms, choose Add / Verify platform and select a platform you control.
  3. Enter your account or profile URL and press Create Social Challenge. Copy the exact text Core gives you to the public location it specifies.
  4. Paste that public location back into Core and press Verify Social Proof. Wait for Core's verified result before calling the proof complete.

For a first proof, GitHub uses a public Gist; YouTube uses the channel About section; TikTok uses a public profile bio. Use the location shown by Core for the platform you chose. A private profile may not be verifiable.

07 · FIND YOUR WAY

What is the Works tab?

Works is your catalog workspace. It separates Certifyd Works, made and managed in Core, from Legacy references connected from outside catalogs. Use it to create drafts, attach files and details, and manage releases.

Connecting a Legacy reference does not turn it into a native Certifyd Work or verify ownership.

08 · FIND YOUR WAY

What is Library?

Library is the view of works you can access. It can include your authored work, purchases, and work shared through splits or derivatives. Filter it by type or relationship to find something you can view or play.

Think of Works as managing your catalog and Library as accessing the work available to you. A Library item does not by itself say you created that work.

09 · SHARING

Choose how people reach Core

Temporary link: a short test or sharing path with no DNS setup. You start and stop it in Core; the address can change.

Named tunnel: a stable custom hostname with a persistent Cloudflare identity. It has a separate guided setup.

Open interactive tunnel guide

Core does not automatically turn a temporary link into a named tunnel. Both public paths target http://127.0.0.1:4010.

10 · PERMANENT ADDRESS

Get a named tunnel

A named tunnel gives your Core a stable public hostname. You need a Cloudflare account and a domain on Cloudflare. The guide checks whether you already have a tunnel, hostname, or running service before it suggests commands.

  1. Open the tunnel guide and choose I want a permanent custom hostname, or the option for your existing tunnel or service.
  2. Follow the steps for your current setup. Confirm the exact tunnel name or UUID and point its public route to http://127.0.0.1:4010.
  3. Check that Core reports the configured public origin and a durable-ready state before relying on buyer links.
Start named-tunnel setup

More than one Cloudflare tunnel on your computer is fine. Do not stop or replace an unrelated tunnel merely because Certifyd shows another one.

11 · PAYMENTS

Connect a payment provider node

For provider-backed commerce, a trusted node supplies payment services while your Core remains the creator's storefront. This is separate from configuring your own Lightning node.

  1. Bring your durable named public origin online first. In Basic mode, provider configuration is hidden.
  2. Open Network → Provider Configuration in Core. Enter the provider's exact Node ID, public key, and URL supplied by its operator.
  3. Save the provider and use Core's Connect provider guided setup. Check its verification and Network Status messages; a saved URL alone does not make it trusted or ready.

If you intend to run your own payment stack instead, use Node Settings · Lightning for your LND connection and readiness test. A named tunnel alone does not enable paid commerce.

12 · MORE CONTROLS

Show the advanced menu

  1. At the bottom of Core's left sidebar, press Show Advanced.
  2. The additional operator section includes Configuration and Diagnostics; Revenue may also become visible.
  3. If a commerce item is still disabled, read its reason in Core. Showing the menu does not grant payment or split capabilities.

Core may show advanced navigation automatically for an Advanced or LAN posture, unless you previously chose a menu preference.

13 · COLLABORATION

Edit a split

A split records who participates in a work and in what percentages. Core requires the appropriate Advanced or LAN and commerce capabilities for split controls.

  1. In Works, choose a Certifyd Work and press Edit splits, or open Manage Splits and choose the work.
  2. In a draft split, add collaborators, roles, and percentages. Review the totals and resolve any participant Core flags.
  3. Save the draft. Lock only when everyone and every share is correct. A locked version cannot be edited; changes require a new version.

If Edit splits is unavailable, the capability message in Core is the source of truth. Turning on Show Advanced does not bypass it.

14 · PUBLISHING

Publish your first work

  1. Create a draft in Works → Certifyd Works.
  2. Add its details and primary file, then review visibility and the available publishing readiness messages.
  3. Publish when the details are ready. A published release is immutable; updated media uses a new version.

Publishing and public reachability are separate decisions. Check the work's actual public URL after publishing rather than assuming a temporary link is a durable buyer address.

15 · NEXT STEPS

Keep exploring

Core also has audience, royalties, payout, and diagnostics views. Follow their in-app status and readiness messages as you add more of your catalog and connections.
