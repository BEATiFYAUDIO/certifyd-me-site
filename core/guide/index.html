01 · START HERE

Install and open Core

Core runs on your own computer. The normal package includes its runtime, so you do not need Git, Node.js, npm, or database commands.

Choose your operating system to see the right launch steps.
Get Certifyd Core Beta 13
02 · FIRST RUN

Create the first owner

  1. Open Core's local dashboard at http://127.0.0.1:4000 if it did not open for you.
  2. On Create owner (first-run setup), make your owner account.
  3. Save the recovery key when Core shows it. It is shown once.

The dashboard on port 4000 is private operator access. Public tunnels use a separate, allowlisted listener on port 4010.

03 · IDENTITY

Make your profile yours

  1. In Core, open Profile.
  2. Add the display name, bio, and profile image you want people to see.
  3. Review the public profile and its presentation settings before sharing its link.

Your local account and its public profile are related, but opening the private dashboard does not put your profile on the internet.

04 · CATALOG

Put a work in your catalog

In Works catalog, choose the path that fits your work:

Choose a work type to see the next step.

A connected Legacy work is a catalog reference, not proof that you own or control the outside account or rights.

05 · PUBLISHING

Prepare a Certifyd Work

  1. Create a draft in Works catalog → Certifyd Works.
  2. Add its details and primary file, then review the preview and visibility choices.
  3. Publish only when the details are ready. A published release is immutable; updates use a new version.

Publishing a work and making Core reachable are separate decisions. A fresh Core install starts private.

06 · SHARING

Choose how people reach Core

Temporary link: a short test or sharing path with no DNS setup. You start and stop it in Core; the address can change.

Named tunnel: a stable custom hostname with a persistent Cloudflare identity. It has a separate guided setup.

Open interactive tunnel guide

Core does not automatically turn a temporary link into a named tunnel. Both public paths target http://127.0.0.1:4010.

07 · NEXT STEPS

Explore when you are ready

Core also has proof, split, commerce, and diagnostics workflows. Their availability and requirements depend on the work and Core's current state. Open those sections in the dashboard and follow their readiness messages before making a public or buyer-facing promise.

This walkthrough covers the first Core journey. It does not change your node or perform an action for you.
