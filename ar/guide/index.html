Viewer path

Read creator context and choose where to go next.

1. Install Certifyd AR

Install the extension for your browser from the Certifyd downloads page. On Android, Certifyd Browser has AR built in.

The desktop downloads currently list 0.1.7 beta packages. Choose your browser below; these are manual beta installs, not an automatic extension-store installation.

Chrome / Chromium
  1. Download the Chrome ZIP from Browser extensions and extract it.
  2. Open chrome://extensions and enable Developer mode.
  3. Choose Load unpacked and select the extracted extension folder containing manifest.json.
  4. Open a supported creator page and choose the Certifyd toolbar icon. If the icon is hidden, find Certifyd in your browser’s extensions menu.
Microsoft Edge
  1. Download and extract the Edge ZIP from Browser extensions.
  2. Open edge://extensions and enable Developer mode.
  3. Choose Load unpacked and select the extracted extension folder containing manifest.json.
  4. Open a supported creator page and choose Certifyd from the toolbar or extensions menu.
Firefox — temporary beta installation
  1. Download and extract the Firefox ZIP from Browser extensions.
  2. Open about:debugging#/runtime/this-firefox.
  3. Choose Load Temporary Add-on, then select manifest.json inside the extracted folder.
  4. Repeat the temporary installation after restarting Firefox. This package is not a permanent Firefox Add-ons installation.
Safari — Apple Silicon beta package
  1. Download the Safari DMG from Browser extensions, open it and drag Certifyd.app to Applications.
  2. Open Certifyd.app once, then open Safari → Settings → Extensions.
  3. Enable Certifyd and grant access to the supported sites you want to use if prompted.

The listed Safari package is for Apple Silicon Macs. Follow the package notes on Downloads; creator publishing on Safari has not been independently verified in this guide’s latest documentation check.

On Android, get Certifyd Browser with AR built in. Desktop extension-install steps do not apply to that app; do not assume every desktop creator control is available in the Android build.

It worked when: You can open the Certifyd icon in your browser. A supported, verified creator page will show its Certifyd information after checking the connection.

2. Explore a supported creator page
  1. Open a creator’s supported social page or Certifyd profile.
  2. Choose the Certifyd icon in your browser to inspect the creator’s profile and verified links. Where the page shows a Certifyd button, use it to open the creator’s public AR actions.
  3. Choose an available action or follow an official profile, website or account link.

It worked when: AR shows the creator’s context for that page. If it cannot check the connection, try again later; a network failure does not mean the creator is unregistered.

On Certifyd Fan, the AR popup offers an introduction to Certifyd. This is an optional, separate discovery application. A supported page for a creator who has not joined may offer an invitation.

3. Supported pages and beta scope

The inspected desktop 0.1.7 packages include connectors for Spotify artist profiles, YouTube creator/channel pages, GitHub profiles and TikTok profiles. Support is page-specific, not site-wide. A private account, missing public proof or changed site layout can prevent verification.

The toolbar popup shows creator identity and official links. On a supported social page, the on-page Certifyd button opens published Reveal, Support and Action content. On a supported Certifyd public profile, the popup can show a published profile promotion. These are different surfaces.

The creator’s Core must be publicly reachable for live checks. An unavailable or uncertain result is not proof that a creator has not joined. AR needs an installed compatible browser extension or supported browser integration; it does not automatically contact followers or bypass platform rules.

Creator path

Editing is available only after you authorize this browser for your own verified profile. Visiting a page alone never grants editing access.

Use browser authorization, then choose the editor for your page: social-page actions or public-profile promotion.

1. Authorize this browser through Core
  1. Verify your profile or outside account in Core. On your verified page, open Certifyd AR and choose Connect this browser, then Copy code.
  2. In Core, open Profile → Connected apps → Certifyd AR. Paste the code, choose Connect Certifyd AR, then Approve connection. Back in the extension, choose Check connection.

Core approves the browser’s permission to publish. Your AR messages are edited and published through AR; opening someone else’s profile does not give you those controls.

Approve from the Core device/browser that holds your creator identity key. Core signs the browser authorization for that identity; account verification alone does not authorize a new browser. Look for Connected in Core and Connected ✓ in AR. If Core says to use the device holding your identity, return to that device rather than creating a replacement identity.

For the Core side, see Connect Certifyd AR in the Core guide.

2. Customize and publish your message
  1. On your verified social page, use the AR popup’s creator editor. Add the Reveal title, text and link; set the Support label and destination; and choose an Action label and destination.
  2. Leave unused actions blank. Reveal needs text or an HTTPS link, not just a title. Support needs both a label and destination: a Lightning address, Bitcoin address or supported payment URI, or an HTTPS support page. Action needs both a label and HTTPS destination. Reveal titles and button labels allow up to 80 characters; Reveal text allows up to 500.
  3. If using Amount (sats, optional), supply a Lightning address and a whole-number amount from 1 to 100,000,000 sats. This configures the support action; it does not confirm a payment.
  4. Choose Save, check Preview as fan (the editor’s viewer preview), then choose Publish. The publishing service must be available, and your Core must be reachable for live authorization checks.

It worked when: AR says Published and a visitor using AR can open your published actions on the supported page. To change your message, edit, save, preview and publish again.

Save stores the signed draft in this browser; Preview as fan previews the form without publishing. Publish sends the saved version, so save again after any changes, even if you already previewed them. Check the public result in a separate viewer browser with AR installed. The on-page Certifyd button remains the viewer panel even in your authorized browser.

3. Publish a promotion on your public profile

This is a separate editor in the downloadable desktop 0.1.7 builds. It appears on your verified Certifyd public profile after browser authorization; it is not the Reveal / Support / Action form on a social page.

  1. Open your public Certifyd profile, then open the AR toolbar popup. Confirm Connected ✓ and Profile promotion.
  2. Enter Headline (up to 100 characters), Offer (up to 80), Description (up to 500) and an HTTPS Destination. All four are required. Use factual copy and a destination you intend visitors to open.
  3. Choose Save, then Preview as fan to inspect the promotion. Choose Publish to publish the saved version; save again if you changed the fields after saving.
  4. Look for Published, then check the public profile’s AR popup in a separate viewer browser. To update it, edit, save, preview and publish again.
  5. To withdraw this profile promotion, choose Deactivate and confirm. This publishes an inactive promotion and needs the publishing service and live authorization; wait for Promotion deactivated.

Deactivate applies to the profile promotion. Do not assume it removes separate social-page actions or deletes your Core profile.

4. Remove or reconnect browser access

In Core → Profile → Connected apps → Certifyd AR, find the relevant device entry, choose Remove access and confirm. This removes its authorization to publish; it is not the same action as deactivating a promotion.

If the extension offers Reset this device, use it only when you intend to replace that browser’s connection code. It creates a new local key; approve the new code in Core, then choose Check connection. Resetting does not remove the old authorization from Core, so remove that old entry separately if it should no longer have access.

Having trouble? Check these first
  • No creator editor: check that this is your verified supported page, Core is publicly reachable, the right identity device approved the code, and AR’s Check connection succeeds.
  • Save locally before publishing: save the current form. Preview alone does not save it.
  • Publishing is not connected yet: this build has no publishing endpoint configured. Use the supported current download or ask for beta support; do not change Core or network settings to guess a fix.
  • Publish failed: check Core reachability and publishing-service availability, then retry. A saved or previewed draft is not a public publication.
  • Viewer sees an old message: save the latest edits and publish again, then refresh the supported page. The profile promotion and social-page actions are separate records.
  • Different controls after an update: for an unpacked Chrome/Edge install, extract the current package, load that folder or reload the existing extension if its files were replaced, then refresh the supported site tab. Firefox temporary installs must be loaded again after a restart.

The 0.1.7 Chrome, Edge and Firefox package code was inspected for these controls. Safari installation follows its published package instructions; Safari and Android creator-publishing parity has not been independently checked here. Paid or encrypted Reveal access is not a supported workflow in this guide.
